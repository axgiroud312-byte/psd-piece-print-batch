# 操作与恢复手册

> 本版本是诊断预发布，不是生产就绪版本。真实 Photoshop、真实 PSD、工厂文件和实物打样仍需分别完成验收。

## 安装诊断构建

1. 在 Windows 安装 Node.js `v24.14.0`。`package.json` 的其他 Node.js 范围只用于一般开发和测试，不能生成本版可重复诊断归档。
2. 确认 Git 工作区干净，再在仓库根目录运行 `npm ci`。
3. 运行 `npm run release:build`；环境或工作区不符合要求时，脚本会拒绝打包。
4. 打开 Adobe UXP Developer Tool，选择 **Add Plugin**。
5. 选择 `release/psd-piece-print-batch-v0.1.0-diagnostic/manifest.json`。
6. 在目标 Photoshop 中加载插件。

也可以解压同名 ZIP，再选择解压目录根部的 `manifest.json`。不得把“成功加载”解释为生产能力已通过；面板会在 M0 完成前保持正式生产锁定。

## 制作模板

模板配置只登记已经人工认可的成品 PSD，不负责自动排版或设计裁片。

1. 固定母版画布尺寸、PPI、颜色模式、位深和 ICC 状态。
2. 为每个裁片登记稳定的图层路径。路径必须与 Photoshop 图层名称和层级完全一致。
3. 每个印花入口对应一个智能对象内容源，并在智能对象顶层保留唯一的 `REPLACE_ART` 替换图层。
4. 需要联动的实例使用相同 `contentSourceId`；必须独立的实例使用不同内容源。
5. 为预览和每个生产裁片登记固定区域、可见图层、工艺标记、格式、透明背景、PPI、位深和 ICC 规则。
6. 使用 `Get-FileHash -Algorithm SHA256 <母版.psd>` 取得母版 SHA-256，写入 `masterFingerprint`。
7. 从 `examples/template-config.example.json` 复制配置，替换全部 `UNVERIFIED` 和占位值。
8. 在插件中导入配置，再选择对应 PSD/PSB。只有文件内容指纹与配置一致时，母版访问门禁才会通过。

`masterSourceRef` 只是本次会话的占位字段。插件保存模板草稿时会删除它，不会把会话 token 写入持久化草稿。

## 输入命名

素材总文件夹必须只有一层分组子文件夹，根目录不能直接放文件：

```text
本次批次/
  款式001-蓝花/
    front.png
    back.jpg
    sleeves.png
  款式002-红花/
    front.png
    back.jpg
    sleeves.jpeg
```

- 子文件夹名称是素材组名称，批次内不能重复。
- 文件名不区分大小写，扩展名前的名称必须等于模板 `artworkEntries[].inputKey`。
- 支持 `.png`、`.jpg`、`.jpeg`；其他扩展名只产生提示，不参与任务指纹。
- 每个必需入口必须恰好匹配一个文件。缺少、重复、无法读取、损坏或尺寸不合规则阻止该组。
- 预检后不要修改素材文件。运行和重试会重新核对内容指纹。

## 日常五阶段操作

当前诊断预发布只提供可检查的操作流和内存诊断试套；正式批次、真实重试与真实恢复服务保持锁定。以下步骤是完成 M0 并接入生产服务后的验收操作规程，不表示本预发布已经具备真实生产能力。

1. **模板**：导入 JSON，选择并校验母版 PSD/PSB，然后保存草稿。
2. **输入**：选择素材总文件夹，查看每组映射和阻止原因。
3. **预览**：当前只能运行诊断试套，不能解锁生产。M0 后必须选择一组执行真实试套，确认输出、裁片、透明背景、标记和颜色规则，再点击“确认试套合格”。
4. **运行**：检查五项门禁全部通过，启动串行批次。面板显示当前组和当前阶段。
5. **结果**：分别处理完成、失败、中断、待确认、处理中和等待组。

模板规则、输出规则或素材内容变化后，旧试套自动失效，必须重新预检和试套。

## 停止和重试

- “安全停止”不是立即终止。插件完成当前不可分割操作后，在安全边界停止，未完成组不会提交。
- 普通素材组失败不会跳过后续合格组；目录级、持久化或清理故障会停止批次。
- 重试前必须重新选择母版和素材，完成预检，并保持模板、素材、配置和插件版本组合指纹一致。
- 重试只处理 `failed` 或 `interrupted` 组；已经完成的组不会重复提交。

## 重启恢复

本节描述生产服务接入后的恢复规程。当前诊断服务不会创建正式运行记录，恢复、目录重选和人工确认入口会保持 fail-closed。

1. 打开“结果”，从选择框选择要处理的中断批次。
2. 如果显示目录访问失效，点击“重新选择失效目录”，依次选择原母版、素材和输出位置。
3. 点击“恢复并核对批次”。系统会核对已经提交的输出，并只清理能够证明归属的临时资源。
4. `running` 和 `queued` 崩溃状态完成对账后会变为完成、中断或待确认，不会直接重试。
5. 如果显示人工清理要求，先在 Photoshop 中确认插件创建的临时文档已经关闭，再点击“我已关闭插件临时文档”。
6. 重新扫描素材并预检；组合指纹一致后，才能重试失败或中断组。

不要手工删除无法确认归属的输出目录或所有权文件。先保留现场，再执行恢复。

## 常见错误

| 提示             | 含义                           | 操作                                                 |
| ---------------- | ------------------------------ | ---------------------------------------------------- |
| 生产能力未验证   | M0 尚未通过                    | 提供 Issue #2 所需材料并完成 Issue #11，不要绕过锁定 |
| 模板配置无效     | JSON、图层路径或输出规则不合规 | 按面板错误修正配置并重新保存                         |
| 母版指纹不一致   | 选择的 PSD/PSB 不是登记母版    | 选择正确文件，或重新登记并重新验收模板               |
| 素材目录授权失效 | UXP 持久目录凭据不可用         | 在结果页重新选择目录，再恢复和预检                   |
| 素材内容已变化   | 扫描后的文件被替换             | 重新扫描、预检和试套                                 |
| 输出需要人工确认 | 提交结果或临时状态无法安全判断 | 保留文件，先恢复对账，再按面板要求人工复核           |
| 操作状态无法保存 | 插件私有存储不可写或数据损坏   | 停止生产，保留运行记录，修复存储后再恢复             |

## 数据安全边界

- 模板草稿不保存 `masterSourceRef`。
- UI 工作区不保存运行记录的目录访问令牌。
- 正式运行记录只能保存 UXP 持久凭据，不能保存短期会话 token。
- 无所有权证明时不自动覆盖或删除已有输出。
- 默认发布服务保持 fail-closed；没有真实 M0 证据时不得启用生产入口。
